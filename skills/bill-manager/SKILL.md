# 远程账单管理

账单数据只允许通过 `bill_manage` 工具写入远程插件数据库。不要直接创建或修改 CSV、SQLite 文件，也不要创建一次性导入脚本。

## 工作流程

1. 从用户原话或远程附件中提取交易记录。附件解析、临时处理和工具调用必须在 Hermes 服务所在主机执行。
2. 为每条记录确定交易时间、交易对方、分类、收支方向和金额。缺少年份、日期、金额、交易对方、分类或收支方向，且无法可靠推断时，写入前提出一个简洁问题。
3. 结合交易对方、商品、备注、支付场景和用户原话判断分类，不使用僵硬的关键词映射。
4. 用户要求预览时设置 `dry_run: true`；确认后再正式调用工具。
5. 单条记录使用 `action: "add"` 和 `record`，多条记录使用一次 `action: "import"` 和 `records`，修改使用 `action: "update"`、`transaction_id` 和 `updates`。
6. 向用户报告新增数、重复跳过数、dry-run 状态和交易单号；不要输出数据库路径之外的隐私数据副本。

## 字段

最小记录：

```json
{
  "transactionTime": "2026/9/24 12:30:00",
  "counterparty": "商户",
  "category": "餐饮",
  "direction": "支出",
  "paymentMethod": "微信支付",
  "amount": 28.5
}
```

工具同时接受英文键和以下中文列名：`交易单号`、`交易对方`、`交易时间`、`交易渠道`、`交易类型`、`创建时间`、`商品`、`备注`、`当前状态`、`支付方式`、`收入/支出`、`金额(元)`。

缺省值：交易渠道为 `其他`，当前状态和支付方式为 `手动记录`，创建时间等于交易时间。日期没有时间时使用 `00:00:00`。两位年份 `26` 表示 `2026`；缺少年份时必须询问。

## 分类

只允许：`餐饮`、`发红包`、`服饰`、`服务`、`工资`、`购物`、`奖金`、`交通`、`教育`、`酒店`、`旅行`、`其他`、`生活缴费`、`退款`、`医疗`、`娱乐`、`转账`、`房租`、`公积金`。

优先选择实际消费或收入目的。仅在上下文确实不足时使用 `其他`。若多个分类仍然合理且会显著影响统计，先询问用户。

收支方向只允许 `收入`、`支出`、`不计入收支`。工资、奖金和实际到账退款通常为收入；购买、支付和缴费通常为支出。

### 亲情卡固定规则

批量导入微信或支付宝流水时，若记录是亲情卡交易、交易对方为家庭成员、商品为空且没有其他上下文，则使用：

- 分类：`转账`
- 备注：`亲情卡交易`
- 收支方向：沿用来源流水中的 `支出`

## 重复与批量原子性

未提供交易单号时，插件按规范化字段生成稳定交易号；微信为 `wx-`，支付宝为 `zfb-`，其他为 `qt-`。同一记录重复执行会被跳过。

批量导入是原子的：任一记录校验失败时整批不写入。修正记录后再重新提交整批数据。
